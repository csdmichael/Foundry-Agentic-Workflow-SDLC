Important architecture rules:
1. Keep configuration separated by tier.
   - UI config must live under the UI tier in a config folder.
   - API config must live under the API tier in a config folder.
   - DB config must live under the DB or persistence tier in a config folder.
   - Agent config must live under an agent or orchestration tier in a config folder.
   - Do not hardcode endpoints, model deployments, API keys, tenant IDs, role mappings, SharePoint URLs, GitHub orgs, ADO orgs, or APIM routes in business logic.

2. Use APIM as the gateway for Foundry APIs.
   - All Foundry calls must go through APIM endpoints.
   - Backend should never call Foundry directly unless a local development config explicitly allows it.
   - Add config for APIM base URL, subscription key or managed identity mode, route names, timeout, retry policy, throttling policy name, and correlation ID header.
   - Add logging hooks for prompt ID, agent ID, model name, token estimate, project ID, user ID, approval gate ID, and workflow run ID.

3. Make every agent model configurable.
   Add an agent configuration file that supports:
   - agentId
   - displayName
   - lifecycleStage
   - modelDeploymentName

   - toolsAllowed
   - mcpServersAllowed

Specialized agents to implement:
- Requirements Agent
  - Reads requirements and UX mockups from SharePoint, OneDrive, or local disk.
  - Summarizes requirements.
  - Generates Epics, Features, User Stories, Tasks, acceptance criteria, and risks.
  - Uses Azure DevOps APIs or Azure DevOps MCP server.

- Architecture Advisor Agent
  - Produces architecture recommendations, design notes, threat model placeholders, API contracts, and implementation plan.
  - Publishes approved design artifacts to SharePoint using configured SharePoint connector/API.

- Code Generation Agent
  - Creates or updates source code repos.
  - Uses GitHub APIs, GitHub Copilot-compatible workflows, or MCP server patterns.
  - Opens branches and pull requests, but must not merge without human approval.

- Test Automation Agent
  - Generates unit, integration, security, and user acceptance test plans.
  - Can create test tasks or pipeline steps.
  - Requires QA or Admin approval before results are marked accepted.

- DevOps / Release Agent
  - Generates or updates pipelines.
  - Provisions Azure resources using configured IaC templates.
  - Must require human approval before provisioning or deployment.
  - Uses managed identity where possible and never stores secrets in code.

- Security and Compliance Agent
  - Reviews generated work items, code, dependencies, and infrastructure plans.
  - Produces findings, risk severity, and remediation tasks.
  - Blocks promotion if required approvals or security checks are missing.

- Knowledge Assistant
  - Searches project docs, SharePoint/OneDrive material, wiki/docs, prior decisions, and operational notes.
  - Provides citations or source references where possible.

Human-in-the-loop requirements:
Implement explicit approval gates across the workflow:
1. Plan and scope approval
2. Architecture and design approval
3. Backlog generation approval
4. Code generation approval
5. Pull request review approval
6. Security review approval
7. Test acceptance approval
8. Release and deployment approval
9. Operate and improve approval

For each approval gate:
- Store approver, role, timestamp, decision, comments, previous state, next state, and artifact references.
- Support approve, reject, request changes, and delegate.
- No agent can advance a workflow stage if requiresHumanApproval is true and approval is missing.
- Show approval status clearly in the UI.
- Add guardrails in both UI and API so bypassing the UI cannot bypass approvals.
- Add audit logs for all approvals and agent actions.
